ADD COLUMN IF NOT EXISTS` and `CREATE [UNIQUE] INDEX IF NOT EXISTS`. Because existing rows receive `dedupKey = NULL` and PostgreSQL treats multiple `NULL` values in a B-tree `UNIQUE` index as distinct, historical duplicate `REMINDER`/`BIRTHDAY` records never break migration deployment, and stranded legacy `SENDING` rows recover via fallback expiration predicates.
